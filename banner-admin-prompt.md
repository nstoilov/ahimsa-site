# Prompt: Banner control UI (Ahimsa admin panel)

## What you're building

A settings screen in this admin panel that controls the promo banner shown on the Ahimsa mobile app's Home screen. Banners are fully remote-driven from the Supabase table `banner_config` — one row per banner slot; your UI reads and writes those rows. This page covers row 1, the **general banner** (see the follow-up prompt at the bottom for row 2, the subscriber banner). The mobile app fetches both rows at launch and re-fetches every 5 minutes, so anything saved here goes live to all users without an app release.

This panel already manages Supabase data (`entries`, `category_order`, etc.). Reuse this project's existing conventions for Supabase queries, forms, validation, toasts, and image uploads — do not introduce new dependencies or patterns.

## The data model (table already exists in Supabase — do NOT recreate it)

```sql
create table public.banner_config (
  id int primary key,
  enabled boolean not null default true,
  title text,
  subtitle text,
  gradient_start text,
  gradient_end text,
  background_color text,
  text_color text,
  image_key text,
  image_large_key text,
  action text not null default 'paywall' check (action in ('paywall','link','none')),
  action_link text,
  updated_at timestamptz not null default now()
);
```

(The table originally had `check (id = 1)` — it has since been dropped, so any id is allowed. The primary key still guarantees one row per id.)

- One row per banner slot: `id = 1` is the general banner (this page), `id = 2` is the subscriber-only banner (follow-up prompt at the bottom). Always read/write the row for the section you're editing; save = upsert on that row's id.
- The nullable fields are nullable ON PURPOSE: `null` means "the app falls back to its built-in default" (defaults listed below). Save `null`, never `""`, for cleared optional fields.

## Field reference — how the mobile app consumes each column

| Column | Type | What it controls | App fallback when null / empty / invalid |
|---|---|---|---|
| `enabled` | boolean | Master on/off. `false` = banner completely hidden. | required (on fetch error or a missing row the app shows no banner — there is no built-in default banner) |
| `title` | text | Bold first line. | `"Отключи пълната библиотека"` |
| `subtitle` | text | Second line. Supports a `{price}` placeholder the app replaces with the RevenueCat monthly price. | `"Само за {price} на месец"` |
| `gradient_start` | text | Gradient top-left color. Must be `#RRGGBB`. **Ignored when `background_color` is set.** | `#E8A33D` |
| `gradient_end` | text | Gradient bottom-right color (also the card's shadow color). Must be `#RRGGBB`. **Ignored when `background_color` is set.** | `#D98A24` |
| `background_color` | text | Solid flat card color. When set (valid `#RRGGBB`), the app renders a solid background instead of the gradient and uses it for the card shadow. | gradient mode (uses the two gradient colors) |
| `text_color` | text | Text color: title at full opacity, subtitle at 85%, chevron at 70%. Must be `#RRGGBB`. | white (`#FFFFFF`) |
| `image_key` | text | Small image left of the text (rendered 44×44, corner radius 8). Stores an **R2 object key under `images/`** — the same key format as `entries.image_url` — NOT a full URL. When not supplied, the app renders the text centered and reserves no image space. | text centered, no image |
| `image_large_key` | text | Large image displayed **below the text**, nearly full card width — 4px inset from the card's left, right and bottom edges, ~8px gap above. The image area is **at most 3:2**: wider-than-3:2 images render in a shorter frame that hugs their aspect; narrower/taller images are capped at the 3:2 height and letterboxed (whole image always visible, never cropped). Corner radius 8. Same R2 `images/` key format. | not shown |
| `action` | text | Tap behavior: `paywall` = opens the subscription paywall; `link` = navigates in-app to the route in `action_link`; `none` = no tap action (chevron hidden). | `paywall` |
| `action_link` | text | Internal app route used when `action = 'link'`, e.g. `/library`, `/player?id=12`, `/breathing`, `/category-entries?id=1` (category links are generated by the panel's Category dropdown). | null (link taps do nothing) |
| `updated_at` | timestamptz | Audit only. Set to `now()` on every save. | — |

App behaviors worth reflecting in the UI copy:

- `action = 'paywall'` banners are only shown to users WITHOUT an active subscription; `link` / `none` banners are shown to everyone (including logged-out users).
- The subscriber banner (row `id = 2`, follow-up below) is shown ONLY to users WITH an active subscription, and when visible it replaces the general banner for them. `paywall` is a meaningless action for it — only `link` / `none` make sense there.
- If `subtitle` contains `{price}` and the app hasn't loaded a price (RevenueCat fetch failed / not yet loaded), the banner is hidden for `link` / `none` actions.
- Invalid hex colors or unknown `action` values are silently replaced with defaults by the app — but validate in the UI anyway so what you see is what users get.

## RLS / write access

- `SELECT` is already open to `anon, authenticated` (public read — the mobile app needs it, including for logged-out users). Do not change it.
- Writes: mirror whatever write path this panel already uses for `entries`. If the panel writes via a service-role key, nothing else is needed. If it writes as authenticated admin users, add policies matching your existing admin pattern, e.g.:

```sql
-- adapt the admin condition to however this panel's admin users are identified
create policy "banner_config admin write"
  on public.banner_config
  for all
  to authenticated
  using (<same admin condition used on entries>)
  with check (<same admin condition used on entries>);
```

Never grant writes to `anon`.

## UI requirements

Add a "Banner" page/section wherever similar management UI lives in this panel, containing:

1. **Status** — toggle for `enabled` (default on).
2. **Text** — inputs for `title` and `subtitle`, both optional. Placeholder text = the app defaults above, so it's clear what an empty field means. Small hint under subtitle: "Use {price} to insert the monthly price."
3. **Appearance** — a background mode switch: **Gradient** (two color pickers / hex inputs for `gradient_start` / `gradient_end`) or **Solid** (one picker stored in `background_color`; when solid is active, disable or hide the gradient pickers — the app ignores them). Plus an optional **text color** picker stored in `text_color` (empty = white). All hex inputs validated as `#RRGGBB` with a live preview strip. Warn (don't block) if the text color and background color/solid have poor contrast.
4. **Images** — two optional uploads, both reusing this project's existing entry-cover image upload flow (must land in R2 under `images/` and produce the object key, not a URL). Each gets a thumbnail preview and a Remove button (remove saves `null`):
   - **Small image** (`image_key`) — shown left of the text (44×44, rounded). When absent, the app centers the text with no image slot, so the preview should switch to centered text too.
   - **Large image** (`image_large_key`) — banner-wide image shown below the text, capped at a 3:2 frame: wider-than-3:2 images make the banner shorter (frame hugs the image); narrower images are contained within the 3:2 max. Never cropped. Uploading 3:2 fills the maximum area with no empty space; preview it with the same cap behavior.
5. **Action** — segmented control / radio: `paywall` | `link` | `none` (default `paywall`). When `link` is selected, show a **Category** dropdown (options from `category_order` plus a `Custom / none` default) — picking a category fills `action_link` with `/category-entries?id=<id>` — above the required `action_link` input, which must start with `/` (the dropdown pre-selects the matching category when the saved link is a category link); otherwise store `null`.
6. **Live preview** — render the banner card exactly as the app does: rounded-16 card with the chosen gradient, or the flat solid color when `background_color` is set; title in `text_color` (or white), subtitle at 85% opacity of it, chevron at 70%; if a small image is set, show it left of left-aligned text, otherwise center the text with no image slot; if a large image is set, show it below the text capped at 3:2 (wider images render shorter); subtitle with `{price}` replaced by a sample like `12,99 лв.`; a `›` chevron at the right end of the text row (hidden when action is `none`). The preview reflects the current unsaved form state.
7. **Load** — on mount, `select * from banner_config where id = 1` and prefill the form. If the row is missing, initialize with app defaults (enabled=true, action=paywall, all optional fields empty) — the first save inserts it.
8. **Save** — a single upsert to id 1 (all fields + `updated_at: now()`). Success toast: "Changes appear in the app within ~5 minutes (or on next app launch)." Surface Supabase errors inline.

## Validation (before save)

- `title`: recommended ≤ 60 chars (single line on the card).
- `subtitle`: recommended ≤ 80 chars; hint if it contains `{price}` while action is `link`/`none` (banner hides when no price is loaded).
- `gradient_start` / `gradient_end`: must match `^#[0-9A-Fa-f]{6}$` or be empty (empty → null). Only used when `background_color` is null.
- `background_color`: must match `^#[0-9A-Fa-f]{6}$` or be empty (empty → null → gradient mode).
- `text_color`: must match `^#[0-9A-Fa-f]{6}$` or be empty (empty → null → white).
- `action`: one of `paywall` | `link` | `none`.
- `action_link`: required and must start with `/` when action is `link`; forced to `null` otherwise (no stale links).
- `image_key`: object key from the upload flow, or `null`.
- `image_large_key`: object key from the upload flow, or `null`; recommended 3:2 aspect (warn if the uploaded image isn't 3:2).

## Non-goals / constraints

- One banner per slot (general + subscriber) — no scheduling, rotation, or history/versioning.
- Don't add columns to the table without coordinating with the mobile app; versions in the wild only know the columns above.
- Never delete a row to hide a banner — use `enabled = false`.
